# 供應商評核系統 - 操作說明

## 🚀 如何啟動系統

### 方法一：使用啟動腳本（推薦，用於部署後的單一服務）

**Windows 系統：**
目前專案未提供對應的 `start.bat`，請改用「方法二：手動啟動」中說明的方式，在兩個視窗分別啟動前端與後端，或在伺服器上使用 PM2 啟動 `server/src/index.js`。

**Linux/Mac 系統：**
```bash
# 給予執行權限（首次執行）
chmod +x start.sh

# 執行啟動腳本
./start.sh
```

### 方法二：手動啟動

**步驟 1：確認前端已建置**
```bash
# 檢查 dist 目錄是否存在
dir dist  # Windows
ls dist    # Linux/Mac

# 如果不存在，先建置前端
npm run build
```

**步驟 2：啟動後端伺服器**
```bash
# 進入後端目錄
cd server

# 啟動伺服器
node src/index.js
```

**步驟 3：訪問系統**
- 打開瀏覽器訪問：`http://localhost:12017`
- 或根據 `.env` 中配置的 `PORT` 訪問

## 🛑 如何關閉系統

### 方法一：在運行視窗中關閉

如果系統是在命令提示字元或終端中啟動的：

**Windows：**
- 在命令提示字元視窗中按 `Ctrl + C`
- 等待伺服器停止

**Linux/Mac：**
- 在終端中按 `Ctrl + C`
- 等待伺服器停止

### 方法二：使用工作管理員/任務管理器

**Windows：**
1. 按 `Ctrl + Shift + Esc` 打開任務管理器
2. 找到 `node.exe` 進程
3. 右鍵點擊 → 結束工作

**Linux/Mac：**
```bash
# 查找 Node.js 進程
ps aux | grep node

# 停止特定進程（替換 PID 為實際進程 ID）
kill <PID>

# 或強制停止
kill -9 <PID>
```

### 方法三：使用 PowerShell 命令（Windows）

```powershell
# 查找並停止所有 Node.js 進程
Get-Process node -ErrorAction SilentlyContinue | Stop-Process -Force

# 或只停止特定端口的進程
netstat -ano | findstr :12017
# 記下 PID，然後執行：
taskkill /PID <PID> /F
```

### 方法四：使用 PM2（如果使用 PM2 管理）

```bash
# 查看運行狀態
pm2 status

# 停止應用
pm2 stop vendor-assessment

# 或停止所有應用
pm2 stop all

# 刪除應用
pm2 delete vendor-assessment
```

## 📋 系統狀態檢查

### 檢查伺服器是否運行

**Windows PowerShell：**
```powershell
# 檢查端口 12017 是否被佔用
netstat -ano | Select-String ":12017"
```

**Linux/Mac：**
```bash
# 檢查端口是否被佔用
lsof -i :12017
# 或
netstat -an | grep 12017
```

### 檢查 Node.js 進程

**Windows：**
```cmd
tasklist | findstr node
```

**Linux/Mac：**
```bash
ps aux | grep node
```

## 🔄 重新啟動系統

1. **先關閉系統**（使用上述任一方法）
2. **等待 2-3 秒**
3. **重新啟動**（使用啟動腳本或手動啟動）

## ⚠️ 常見問題

### 問題：端口已被佔用

**錯誤訊息：** `Error: listen EADDRINUSE: address already in use :::12017`

**解決方法：**
1. 找到佔用端口的進程並關閉（見上方「如何關閉系統」）
2. 或修改 `server/.env` 中的 `PORT` 為其他端口

### 問題：無法訪問網頁

**檢查清單：**
- ✅ 伺服器是否正在運行？
- ✅ 端口號是否正確？
- ✅ 防火牆是否允許該端口？
- ✅ 瀏覽器是否訪問正確的 URL？

### 問題：資料庫連接失敗

**檢查：**
- ✅ `server/.env` 中的 `DATABASE_URL` 是否正確
- ✅ 資料庫服務是否運行
- ✅ 網路連接是否正常
