# 功能對照與重建路線（Feature Parity + 擴充）

> 更新：2026-07-29（重新定調 v2）
> **原則**：不是「精簡版 MVP」，而是 **保留原系統既有全部功能 → 乾淨架構重建 → 合理擴充/整合**。要點：
> 1. 評分做成「可設定」的管理畫面。
> 2. **背調 / 比價 / AI 排名 要「早做」**（屬核心目標，不延後）。
> 3. **系統要看得出「模組區分」**：導覽/IA 要顯示 SQM/VQM、OSAT、背調、比價、AI、管理 等模組結構；即使 OSAT 目前無資料，也以「模組存在但未啟用」呈現，不能讓人進來只看到「儀表板+評分」。
> 4. OSAT 是否實作待確認，但**結構上要先露出**。細節後續與 user 討論。

## 建置順序（滾動調整）

0. **模組化 IA / 導覽**：讓 SQM/VQM、OSAT、背調、比價、AI、管理 模組結構在畫面上可見（未建置者以「建置中/未啟用」佔位）（← 現在做）
1. **管理層**：供應商管理 + 帳號管理（← 現在做）
2. **可設定評分**：評分規則管理畫面 + 引擎接受設定覆寫
3. **報表 parity**：年度評鑑、季度三報表細節、Excel 匯入匯出
4. **背調 / 比價 擴充**（早做，核心目標）
5. **AI 問答 + 後台**（含未來 AI 供應商排名）
6. **OSAT**（結構先露出；實作待確認）

> 原則：每個模組重建時「行為對齊原系統 → 再做合理整合/優化」；舊 `src/` + `server/` 保留為對照參考，不刪。
