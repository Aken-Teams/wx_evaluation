# 季度供應商評比 — 評分規則（現況萃取，待客戶確認）

> 產生日期：2026-07-29
> 來源：**直接從現行程式碼萃取**（`src/services/reportService.ts`），非舊版文件（舊版 `計算規則與判定邏輯說明.md` 公式已與程式碼不符，不採用）。
> 用途：① 重做時作為「規格書」；② 給客戶（無錫）確認公式是否正確；③ 作為對拍測試基準。
> 註：客戶提供的 `比价信息表.xlsx` 為「比價/背調」用途，**不含**季度評分公式，故評分邏輯以本文件（現行程式）為準。

---

## 0. 總覽

**綜合評分（滿分 100）= 品質總分（70）＋ 交期分數（20）＋ 服務分數（10）**

再依綜合評分對照等級 A~E，最後套用降級規則得出最終等級。

| 構面 | 滿分 | 對應客戶說法 |
|------|:---:|------|
| 品質 | 70 | 品質 |
| 交期（採購評核） | 20 | 交期 |
| 服務 | 10 | 服務 |

---

## 1. 品質總分（滿分 70）= LAR 評分（30）＋ CAR 評分（40）

### 1.1 LAR 評分（滿分 30，依批退良率階梯）
- `LAR% = 檢驗批數為 0 時視為 100；否則 (1 − 退貨批數 ÷ 檢驗批數) × 100`

| LAR% 區間 | 分數 |
|-----------|:---:|
| ≥ 100 | 30 |
| ≥ 99 | 28 |
| ≥ 95 | 26 |
| ≥ 85 | 22 |
| ≥ 80 | 18 |
| ≥ 75 | 14 |
| < 75 | 0 |

### 1.2 CAR 評分（滿分 40，扣分制）
```
CAR 評分 = max(0, 40 − 10×外部客訴件數 − 5×產線CAR件數 − 3×延遲回覆件數)
```
（最低 0 分）

### 1.3 品質總分
```
品質總分 = LAR 評分 + CAR 評分   （滿分 30 + 40 = 70）
```

---

## 2. 交期分數（採購評核，滿分 20，扣分制）

### 2.1 達交率扣分
| 達交率 | 扣分 |
|--------|:---:|
| ≥ 99.5% | 0 |
| ≥ 95% | 5 |
| ≥ 90% | 10 |
| ≥ 85% | 15 |
| < 85% | 20 |
（達交率未填時預設 100%）

### 2.2 交期分數
```
交期分數 = max(0, 20 − 達交率扣分 − 20×產線停線次數 − 特批扣分)
```
（最低 0 分）

---

## 3. 服務分數（滿分 10，人工輸入）
```
服務分數 = 品質構面服務評分 + 採購構面服務評分   （合計 0~10）
```

---

## 4. 綜合評分與等級

```
綜合評分 = 品質總分 + 交期分數 + 服務分數   （滿分 100）
```

### 等級門檻（區間：下界不含、上界含）
供應商分 **AU / Non-AU** 兩套門檻（「是否 AU」為自由文字，內容含「AU」視為 AU）：

| 等級 | Non-AU | AU（較嚴） |
|:---:|:---:|:---:|
| A | > 95 | > 98 |
| B | > 85 | > 90 |
| C | > 75 | > 80 |
| D | > 60 | > 70 |
| E | ≤ 60 | ≤ 70 |

---

## 5. 降級規則

### 規則 1~3：單季低分降級（品質或交期過低）
| 目前等級 | 觸發條件 | 降為 |
|:---:|------|:---:|
| A | 品質總分 < 56 **或** 交期分數 < 15 | B |
| B | 品質總分 < 56 **或** 交期分數 < 15 | C |
| C | 品質總分 < 56 **且** 交期分數 < 15 | D |
（每次降一級；D、E 不再因此規則降級）

### 規則 4：連續低等級再降級
```
若「本季」與「上一季」等級皆為 C 或 D → 最終等級再往下降 1 級
```

---

## 6. 「本季無交易」判定
當以下**全部為 0** 時，該供應商本季視為「無交易」：
- 檢驗批數 = 0
- 退貨批數 = 0
- 外部客訴件數 = 0
- 產線CAR件數 = 0
- 延遲回覆件數 = 0
- 服務評分 = 0

→ 品質總分／交期／服務／綜合評分／降級決策／等級 六欄一律顯示「—」，備註固定為「本季無交易」。

## 7. 待客戶確認的疑點（重做前釐清）

1. **舊文件與程式不一致**：舊版說明文件寫品質基數為 `90 − 2×ARR − 2×LRR − 10×客訴 − 5×未準時`，但程式實際是本文件的 `40 − 10×外部客訴 − 5×產線CAR − 3×延遲回覆`。**請確認以程式（本文件）為準。**
2. **LRR 未參與計分**：程式讀入 `lrr` 欄位但未用於任何評分公式，僅顯示。是否應納入？
3. **AU/Non-AU 兩套門檻**：確認 AU 的定義與更嚴門檻是否正確。
4. **達交率預設 100%**：未填視為滿分，是否合理？
5. **「服務」如何取得**：目前是人工輸入 0~10，客戶是否有客觀衡量標準？
