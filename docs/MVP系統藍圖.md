# 供應商評比系統 — MVP 系統藍圖（功能面 → 底層設計）

> 產生日期：2026-07-29　｜　搭配：[重構分析報告.md](重構分析報告.md)、[重構計畫書.md](重構計畫書.md)
> 溝通原則：**從「使用者要做什麼」出發，反推「底層要怎麼設計」**。
> 對象：無錫獨立部署（台灣/無錫 DB 不共用，本系統只服務無錫這一套）。

---

## 1. MVP 定位

> **一句話**：工程師能「快速評比」供應商，長官能「看到分析」做決策。

- 核心痛點：現況是 email + 手動 Excel + 人工評分 → **太手動、太薄弱**。MVP 的價值＝**把評比變快、把結果變成可看的分析**。
- **MVP 涵蓋**：登入/權限、供應商主檔、季度評比（工程師）、分析儀表板（長官）。
- **MVP 不涵蓋、但架構預留接口**：背調分析、比價/尋源、AI 供應商推薦排名。

---

## 2. 使用者角色（決定畫面與權限）

| 角色 | 主要動作 | 看到什麼 |
|------|----------|----------|
| **工程師（評核者）** | 每季輸入/匯入資料、快速完成評比 | 評比作業畫面、自己負責的供應商 |
| **長官（決策者）** | 看分析、比較、排名 | 唯讀儀表板、跨供應商比較 |
| **管理員** | 管帳號、管供應商主檔、管評分規則 | 全部 + 設定頁 |

## 3. 功能清單 → 底層設計（核心章節）

> 每個功能：**使用流程 → 需要的資料 → 反推的底層設計**。

### F1. 登入與權限
- **使用流程**：登入 → 依角色進不同首頁（工程師進評比、長官進儀表板）。
- **需要的資料**：使用者（帳號、密碼雜湊、角色、啟用狀態）。
- **底層設計**：
  - `User` 表；密碼 bcrypt；JWT。
  - **資安修正（現有系統痛點）**：角色權限**後端強制驗證**（前端只做畫面切換，不可信）；token 建議 httpOnly cookie 或至少縮短效期；統一權限中介層（現有有 3 種寫法要收斂成一種）。
  - **帳號來源（定稿）**：MVP **先自建帳號**（讓大家先看感覺），架構預留 **AD/SSO** 接口，日後整合不需打掉重做。

### F2. 供應商主檔
- **使用流程**：管理員維護供應商清單；評比時從清單選供應商。
- **需要的資料**：供應商基本資料（名稱、供應商代碼、物料類別、地區、狀態…）。
- **底層設計**：
  - `Supplier` 表（取代現有 `SQMVQMVendor`，欄位重新整理）。
  - 支援 **Excel 批量匯入**（現有有，保留並優化）。
  - 為未來背調/比價預留：供應商可掛「背調資料」「歷史報價」（MVP 先不做，但 FK 結構想好）。

### F3. 季度評比（工程師）★ MVP 重心
- **使用流程（自動化優先）**：
  1. 選季度 + 供應商 →
  2. **系統自動帶出上季資料 / 或匯入 Excel 預填**（減少手打）→
  3. 工程師只需填「本季有變動的數字」→
  4. **系統即時自動算分**（品質/服務/交期 → 綜合分 → 等級 A~E）→
  5. 存檔（草稿/正式）、可一鍵匯出。
- **需要的資料**：
  - 評比週期（年、季）
  - 每家供應商每季一筆評比紀錄，含三構面的原始指標：
    - **品質**：退貨/批退、客訴(CCR)、糾正措施(CAR)、回覆準時性…
    - **服務**：服務品質、配合度、特批…
    - **交期**：達交率、延遲交貨…
  - 計算結果：品質分、採購(服務+交期)分、綜合分、等級。
- **底層設計**：
  - `EvaluationPeriod`（年/季）、`Evaluation`（供應商×週期，存原始指標）、`EvaluationScore`（存計算結果）。
  - **彈性評分引擎**（見 §4.2）：把「指標 → 分數 → 加權 → 等級」抽成設定驅動，不寫死在程式各處（現有系統的最大毛病是計算邏輯複製 4 份）。
  - **沿用現有計算公式作為規格（定稿）**：MVP **不改評分規則**。公式已從實際程式精準萃取成 [評分規則_現況萃取.md](評分規則_現況萃取.md)（品質70=LAR30階梯+CAR40扣分、交期20=達交率扣分制、服務10、綜合100、A~E 含 AU/Non-AU 雙門檻、降級規則）。客戶提供的 `比价信息表.xlsx` 不含評分公式，故以現行程式為準。萃取為單一評分引擎模組 + 對拍測試（確保重寫後每筆分數與現況一致）。
  - **自動化機制**：上季帶入（複製上季紀錄為草稿）、Excel 匯入映射、即時計算（前端輸入即算，不用按鈕）、欄位驗證。

### F4. 分析儀表板（長官）★ MVP 重心
- **使用流程（定稿：全做，以客戶給長官看的東西為藍本 + 市面 SRM 標準項目）**：長官登入 → 一頁看到：
  - **KPI 卡**：總供應商數、平均綜合分、A 級家數、本季被降級家數
  - 本季**供應商排名榜**（依綜合分/等級）
  - **等級分布**（A~E 各幾家）
  - **多家並排比較表**（仿 `比价信息表.xlsx`，多供應商跨維度並排）
  - **雷達比較**（多家在品質/服務/交期三軸並排）
  - **分數趨勢**（單一供應商跨季走勢 + 整體走勢）
  - **風險觀察名單**（分數下滑、連續低等級 C/D 的供應商）
  - 點一家 → **drill-down** 看該供應商歷史、明細、備註。
- **需要的資料**：來自 F3 累積的 `EvaluationScore`，做聚合查詢。
- **底層設計**：
  - 後端提供**聚合查詢 API**（排名、跨季趨勢、跨供應商比較），不是把原始資料丟前端算。
  - 前端用圖表（長條/雷達/折線）+ 可排序表格。
  - **設計成「可加維度」**：MVP 是品質/服務/交期三軸，之後加背調就是多一軸，儀表板元件要能吃動態維度。
  - 這一層就是未來 AI 排名的資料基礎（AI 排名 = 對這些結構化分數做動態加權查詢）。

## 4. 從功能導出的資料模型

### 4.1 核心實體（MVP）
```
User(角色)                         Supplier(供應商主檔)
                                      │ 1:N
                                      ▼
EvaluationPeriod(年,季) ──1:N──►  Evaluation(供應商×週期, 原始指標)
                                      │ 1:1
                                      ▼
                                   EvaluationScore(品質分/服務分/交期分/綜合分/等級)

（預留, MVP 不實作）
Supplier ──1:N──► BackgroundCheck(背調: 拖欠貨款/客訴/8D/配合度)
Supplier ──1:N──► Quote(比價: 報價/議價/賬期/級距單價)
```

### 4.2 彈性評分引擎（整個系統的心臟）
把評分「設定化」，不寫死：
```
ScoreDimension   維度（品質/服務/交期… 未來可加背調）
  └ Metric       指標（退貨率/客訴/達交率…）+ 計分規則（階梯/公式/門檻）
  └ Weight       權重（品質70% 服務/交期30%… 可調）
GradeThreshold   等級門檻（A≥95 / B≥85 …）
```
- **好處①**：計算邏輯只有一份、由設定驅動 → 消滅現有「四處複製」。
- **好處②**：加新維度（背調）= 加設定，不用改一堆程式。
- **好處③**：AI 排名要的「動態加權」（這次重價格、下次重交期）＝改權重即可 → 為終極願景鋪路。

## 5. 從功能導出的系統架構

```
┌── 前端 (React 重新設計) ───────────────────────────┐
│  角色導向: 工程師→評比工作台 / 長官→儀表板          │
│  UI/UX 重做: 專業商務風 (丟棄現有早期Claude紫) ·圖表 │
│  資料抓取用快取層 (取代現有手刻)                    │
└───────────────┬────────────────────────────────────┘
                │ 型別化 API
┌───────────────▼────────────────────────────────────┐
│  後端 (分層: routes/controllers/services)           │
│  ├ 評分引擎 (設定驅動, 單一真相 + 測試)             │
│  ├ 聚合查詢 (排名/趨勢/比較)                        │
│  └ 統一權限/驗證/錯誤處理 (修現有資安)              │
└───────────────┬────────────────────────────────────┘
                │ Prisma (加交易)
┌───────────────▼────────────────────────────────────┐
│  MySQL (無錫, 經 cloudflared SSH 跳板)              │
│  啟動即自動連通道 + 穩定重連 (現有 db-tunnel 強化) │
└─────────────────────────────────────────────────────┘
```

**部署（定稿）**：非 Docker，**先部署在「我們公司」**（Node + PM2），待客戶確定後再議是否移到無錫。
> ⚠️ 重要連動：既然先放我們公司（不在無錫內網），**正式環境也必須走 cloudflared SSH 跳板**才連得到無錫 DB。因此「啟動即自動連通道 + 穩定重連 + 健康檢查 + 連不上降級」不只是開發便利，而是 **production 等級的必要條件**，須按正式服務標準設計。

## 6. 自動化設計（直接回應「太手動」痛點）

| 現況（手動） | MVP（自動化） |
|--------------|----------------|
| 逐欄手打數字 | 上季資料自動帶入，只改變動處 |
| 人工算分 | 輸入即時自動算分、算等級 |
| email 收 Excel 再整理 | 直接 Excel 匯入映射預填 |
| 人工整理給長官看 | 長官自助登入看即時儀表板 |
| 手動做比較表 | 系統自動多維比較/排名 |

## 7. 後續擴充接口（MVP 之後怎麼接上願景）

- **背調** → 在評分引擎多加一個 `ScoreDimension`（背調的 4 項）+ `BackgroundCheck` 表；儀表板自動多一軸。
- **比價/尋源** → 新增 `Quote` 表 + 比價比較畫面（多家並排，像 Excel）；背調資料可直接引用評比累積的品質/客訴數據。
- **AI 供應商推薦排名** → 對結構化的分數做「動態加權查詢」；AI 把「我要 X 類廠商」翻成維度權重 → 引擎排名 → 回推薦。因為資料一開始就結構化，這一步是**查詢**而非重算。
